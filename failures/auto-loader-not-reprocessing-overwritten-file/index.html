Auto Loader · Discovery · failure 07 of 16

The corrected re-upload never took effect.

Failure family · Discovery Auto Loader · part 06 · failure 07 of 16
Symptom
The vendor corrected a bad record and re-uploaded the file at the same path. Your table still shows the old values.
Cause
Same path means already seen, so it is skipped. This is by design — the path is the file's identity.
Fix
There is a partial fix and a real fix. cloudFiles.allowOverwrites makes Auto Loader reprocess a file when its modification time changes — but it appends rather than replaces, so you now hold both the old and the corrected rows and still need deduplication downstream. The real fix is to have the source write a new path and resolve versions with a MERGE in silver.

Check first — If the same bytes keep arriving at the same path, you have a snapshot problem rather than an incremental file problem. Solve it with MERGE or overwrite semantics, not with discovery options.
